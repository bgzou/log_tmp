## 1. 一键会话脚本 `run_r214_field_session.sh`

### 1.1 位置与调用

脚本在 CPRO 上：`/root/as2w_deploy/tools/run_r214_field_session.sh`（源码 `部署参考/cpp_deploy-as2w/tools/run_r214_field_session.sh`，源=CPRO 需 SHA 一致）。从工作站/服务器一条命令调用（服务器经工作站 PowerShell 转发 hdc）：

```
ssh -i ~/.ssh/as2w_workstation zoubu@192.168.10.61 "powershell.exe -NoProfile -Command \"& '<hdc.exe完整路径>' shell /data/local/tmp/as2w_field/cpro_ubuntu.sh /bin/bash -lc 'cd /root/as2w_deploy && bash tools/run_r214_field_session.sh stand'\""
```

参数：`stand`（默认，A 起立/Y 趴下，已三次真机通过）｜`zero-b`（B 单次零速+自动回站趴下）｜`motion`（全方向摇杆；**当前行走塌陷未修复，禁止对狗使用**，只可用于流程演练）｜`dry-run`（只跑步骤 1-4 校验，不做任何动作）｜第二参数监测秒数（默认 150）。

### 1.2 脚本步骤（全部不可跳过——两次报警的教训）

| 步骤 | 内容 | 失败行为 |
| --- | --- | --- |
| 1 前置校验 | 发布端二进制存在；源码+二进制 SHA256 记录到会话日志；`--offline-audit` 必须 PASS | 立即退出 |
| 2 DDS 探测 | LowState 1 秒 ≥100 包且 `mode_machine=2` | 退出（狗/链路异常） |
| 3 控制权 | `CheckMode`：`name=ai`（原厂）→ 确认趴下（站立则官方 `stand-down`，RPC 不灵则提示遥控器趴下，最多等 60s）→ `ReleaseMode` → 复核 name 为空；`name=` 空（已释放）→ 直接继续 | 任一失败退出；**绝不在未趴下时 ReleaseMode** |
| 4 质量校验 | LowState 2 秒 ≥1500 包；**16 轴反馈 mode 全 0**——若非 0 说明有别的进程在发 LowCmd（两次报警的同型风险），强制退出 | 退出 |
| 5 监测 | CPRO 本地后台 `low-capture`（10ms）+ `low-protection`，日志在会话目录 | — |
| 6 启动发布端 | 调用对应 launcher；发布端**内部自带已验证唤醒序列**：500ms 只读观察 → 16 轴中性唤醒(mode=1/q 跟随/全零增益) → FOC 回读稳定 200ms → kd 0→3 渐升 → `Passive ready` → 手柄可接管 | — |

结束：打印退出码与会话目录 `/root/field_sessions/<时间戳>_<模式>/`（session.log、publisher.log、low_capture_fast.log、low_protection.log）。**事后必须**把整个目录拷回工作站 `部署测试/04_调试记录/logs/` 并追加 INDEX（监测输出是块缓冲，发布端 RC=0 即逻辑结束，挂住的会话可 pkill——见 `../AGENTS.md`）。

### 1.3 会话中的手柄语义（P6 实测解码）

| 键 | 动作 | 状态 |
| --- | --- | --- |
| A | 趴下→两段 FixStand 起立→固定 PD 站立；策略中=先刹车回固定 PD | ✅ |
| B | 固定站→(门槛校验)→2s 平滑交接→R214 策略 | ✅ 零速两次通过；**行走塌陷待修** |
| Y | 固定站/策略中→两段连续 FixSquat 受控趴下 | ✅ |
| X | 任意时刻紧急 Passive（站立时可能下沉） | ✅（有效但站立下沉风险） |
| 摇杆 | 只在 motion 模式映射策略速度（\|vx\|≤0.1、\|vy\|≤0.05、\|wz\|≤0.1） | ⚠️ 行走暂停 |

**B 接受门槛**（`r214_publish.cpp` 常量，含物理依据注释）：腿 pose_error≤0.35 + 轮 |dq|≤0.5 + 摇杆居中 + 站立≥0.5s + 最近 500ms 腿静止 + upright≥0.9；拒绝会打印 12 轴逐轴误差，**被拒后不要反复按**，按 Y 退出或等 15s 超时自动趴下。

## 2. 策略模型更新 SOP（同事交付新模型时）

**先决**：同事必须同时交付 `policy.onnx` **和** 新的 `r214-trace.csv`（训练侧导出的 1050 帧观测-动作对照）+ 模型 SHA256 + 训练命令域说明。

1. **先审训练命令域**（2026-11-10 踩过的坑）：解析 trace 第 1-3 列 command 分布（[flag,obs41,action16] 布局）。R214 旧模型只有 vx∈{0.4 主,0.35,0}、vy 恒 0、wz∈{0,−0.5}——**摇杆指令超出训练域就是 OOD**。新模型若命令域不同，1.3 的摇杆限幅与语义必须同步改。
2. 放置：`models/r214/policy.onnx`、`models/r214/r214-trace.csv`（工作站权威目录），核对 SHA256 三处一致（工作站→镜像→CPRO `hdc file send`）。
3. **校验链（顺序执行，不可跳过）**：
   a. `as2w_r214_replay models/r214/deploy.yaml models/r214/r214-trace.csv` → 1050 帧 max_abs_error ≈ e-07 量级（模型自洽）
   b. `--offline-audit` PASS（含 FSM 合同、唤醒时序、帧字段）
   c. 三构建增量编译+CTest 各 8/8（stand/zero-b/full，CMake 选项见下）
   d. 服务器 MuJoCo 复演（`部署参考/as2w-flat-rerun/r214_zero_b_trial_rehearsal.py` 等；三种子 A→Y 与 A→B零速→回站→Y 至少各一遍）
   e. 真机：**zero-b 模式先行**（不碰摇杆），通过后才允许 motion。
4. R214 本模型的策略增益合同：腿 kp=55/kd=2、轮 kp=0/kd=2（dq=16×action），与该模型训练/交付一致。它只约束R214策略状态，**不是跨策略不可修改的全局常量**；FixStand/FixSquat本来就使用不同增益，新策略必须核对自己的训练和部署合同后独立配置。GO2 的25/0.5也不能未经核对直接搬用。
5. 更新 `models/r214/manifest.json`（若存在）与 INDEX 记录新 SHA。

## 3. 添加新按键 / 新策略的开发指南（配置化改造蓝图）

### 3.1 现状：policy-specific 参数硬编码位置

`deploy/robots/as2w/r214/r214_publish.cpp`（唯一发布源码，约 1600 行）当前硬编码：
- 姿势：`make_stand_t1()`（实测工厂站姿）、`make_prone()`（实测趴姿）、T2=`deploy.yaml:default_joint_pos`
- 增益：固定 PD kp=55/kd=2；FixStand 两段 kp 20/55；FixSquat kp 35→20→10→0；Passive kd=3；轮 kd=2
- 时序：FixStand 3s（60/40 分段）、FixSquat F1 1.5s/F2 2.5s/衰减 3s、PolicyHandoff 2s、ReturnStand 2.5s
- B 门槛常量 `kBGate*`；摇杆映射与限幅（`map_remote_command`）
- FSM 状态集与转移（switch-case 硬编码）

`deploy.yaml`（config 化的部分）：joint_names、defaults(T2)、position/velocity limits、command_limit、step_dt、model 路径。

### 3.2 GO2 参考结构（`unitree_cpp_deploy-go2/deploy/robots/go2/config/config.yaml`）

```yaml
FSM:
  _:            # 状态注册表（id + type: Fix/RLBase）
  Passive:      # 每状态：transitions（事件→目标状态）、mode/kd
    transitions: {FixStand: "LT + A.on_pressed"}
    kd: [3,3,...]
  FixStand:     # Fix 型：kp/kd 时间序列 ts + 关键姿势序列 qs
    transitions: {...}
    kp/kd/ts/qs: [...]
  Velocity_Up:  # RLBase 型：接策略，摇杆映射速度
    transitions: {...}
```

GO2 的按键事件 DSL（`LT + A.on_pressed`、`start + up`）由 `CtrlFSM`+`unitree_joystick_dsl.hpp` 解释；状态实现类（State_Passive/State_Fix/State_RLBase）在 `deploy/include/FSM/` 注册（`REGISTER_FSM`）。

### 3.3 建议的 R214 配置化方案（渐进，不做大爆炸重构）

**原则：先参数后结构。** 第一步只把"数值"搬进 `deploy.yaml`（代码读 config，缺省=当前值，行为不变）；第二步才考虑转移表 DSL 化。每步：增量编译+CTest+audit+MuJoCo+按门槛真机复验（A/Y 必过，新状态按 zero-b 式有界首测）。

建议 schema（加到 `models/r214/deploy.yaml`，复用现有 Config 加载框架 `r214_controller.cpp:load_config`）：

```yaml
fsm:
  fixed_stand:      {kp: 55, kd: 2, seg1_frac: 0.6, seg1_kp: 20, interp_sec: 3}
  fix_squat:        {f1_sec: 1.5, f2_sec: 2.5, kp1: 35, kp2: 20, thigh_delta: 0.2, calf_delta: -0.3, release_sec: 3}
  passive:          {kd: 3, seconds: 3}
  handoff:         {blend_sec: 2, zero_hold_sec: 10}
  b_gate:          {pose_error: 0.35, wheel_dq: 0.5, quiet_dq: 0.15, quiet_ms: 500, min_hold_ms: 500, upright: 0.9}
  remote_map:       {vx_limit: 0.1, vy_limit: 0.05, wz_limit: 0.1, deadzone: 0.05, axis_scale: 0.85}
  poses:            {prone: [-0.5676, 0.5725, -0.5930, 0.6040, 1,1,1,1, -2.75,-2.75,-2.75,-2.75, 0,0,0,0]}
```

**新增组合键+新策略的步骤模板**（例：新增"Select+右摇杆上=切换到策略 P2"）：
1. （若新模型）按第 2 节 SOP 交付/校验模型，得到新 `Controller` 实例（每个策略独立 state[1196] 生命周期，`arm()/stop()` 只在切换边沿调用）。
2. `deploy.yaml` 加状态段：`p2_walk: {policy: models/p2/policy.onnx, trace: ..., transitions: {"select+ry_up": FromState}}`。
3. `r214_publish.cpp` 枚举加 `State::P2Walk`；FSM case 里：进入时**连续 blend**（复用 `blend_targets`，目标 q/kp/kd 全插值，参考 PolicyHandoff 的 2s 模式）；退出走 Brake→冻结目标→ReturnStand 模式（已三次真机验证的安全返回路径）。
4. 摇杆解码：P6 位图里 `bit0-7 未测`（R1/L1/R2/L2 等），新组合键先做只读解码会话确认位与上升沿，再接线（`decode_remote`+`button_pressed` 模式照抄）。
5. 离线门槛全过（编译/CTest/audit/回放/MuJoCo 三种子）→ 写单次许可话术（具体动作/风险/自动退出）→ 真机首测限定**零速有界窗**（复刻 zero-b 模式：强制零速+自动回站+超时自动趴下），不直接放开摇杆。
6. INDEX 归档每一轮。

### 3.4 修改源码后的固定流程（增量编译，勿冷编）

见 `../AGENTS.md`"服务器 x86 编译流程"：工作站编辑 → `cp` 单文件到 `/tmp/opencode/r214_zero_b` 镜像 → `cmake --build b --target as2w_r214_publish -j8`（约 5s）→ audit+CTest → `hdc file send` 推 CPRO → 三构建 `cmake --build build-r214-ab-fsm{,-full}` + `build-r214-zero-b` 增量+CTest → 三处源码 SHA 一致 → 才可申请真机。复杂 CPRO 命令一律 base64 脚本传输（多层转义规则同文件）。

## 4. 已知限制（2026-11-10 收官状态）

- R214 平地行走**不可用**：后腿后仰塌陷（机制 B：策略目标偏高倾 −7°、kp=55 在实机质心偏后下撑不到，后腿 cmd−actual 锁定 +0.35~0.45）；侧移/旋转训练命令域缺失无动作。修复方向=策略输出与 T2 按比例混合托底（先 MuJoCo 扫混合比），修复后按本页门槛复验。
- 塌陷不可逆但 **A 回站三次从 −19~−22° 完全拉正**，X/物理急停始终可用；急停是**锁存式**，解除后才可重新上电。
- `SelectMode("ai")` 会让趴下的狗**直接起立**（P4 实测）——恢复原厂是动作，须单独许可。
- 低层失联超时语义、轮速精确标定仍未验证；任何新固件/新机器先跑 dry-run。
