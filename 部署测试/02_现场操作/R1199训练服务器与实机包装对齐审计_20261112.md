## 2. 停走抬升/下降：最强的部署侧差异

当前 C++ `hold_frames` 被非零命令重置，约4秒后站姿修正系数可在20ms内从1归0；真实训练/正式评估 `continuous=true,straight_only=true` 的 Python 分支对纯前后直行保留按直立程度缩放的校准补偿。两次实机首次推杆都分别触发 `0.272911/0.254249rad` 的腿目标单帧软件预警，随后实测腿姿态由高变低，松杆后又渐渐抬身。**训练与实机开关不一致、C++存在目标跳步、现场姿态突变三条证据相互吻合**。仍须同条件离线消融，确认补偿开关改变后没有引入轮卸载或触地等副作用；不能直接上狗切开关。

`park_odometry/park_settle_joints` 也不一致，可能改变松杆后停车锁存与轮角参考；它们不是上述“非零命令一帧撤补偿”的必要条件。明日先只改站立补偿，之后分别消融停车两项，避免把四个变量一起改而无法定位。

## 3. 前后滚动中可闻抖动：证实存在，来源尚未隔离

现场两次都听到；第二次约100Hz状态采样中，持续前进时 12 腿 `dq` RMS `0.1113rad/s`，对照静止 `0.0066`；腿估算力矩去0.2秒慢变化 RMS `0.6799Nm`，对照 `0.0181`。前进内部 FR 髋有成串正负交替，见外发包 `evidence/derived/motion_jitter.png`。两轮硬件保护位全0，仅首次推杆触发一次软件目标步进 warn，**保护位全0不代表机械抖动不存在**。

目前证据最多支持以下待检链路，不能把它们写成已证实根因：

1. **包装分支不一致改变承重**。实机直行时整项撤掉补偿，使髋目标误差约从0.35–0.45降到0.12–0.20rad，髋承载力矩也改变，可能让轮地接触和腿PD在运动时反复修正；若训练分支保留补偿，则两边接触动力学不同。明日同权重对比 `false/false` 与 `true/true` 的持续直行目标和轮载。
2. **训练任务与极低速细推的分布差异**。当前训练源码的滚动速度课程包含标称0.10m/s和更高随机值、零速/制动、约1–3秒命令段；实机本次多次约0.005–0.05m/s短推。连续随机变量可能含0.05，故不能断言“训练从未见过”，但精确占比/停走次数缺少统计。正确训练合同速度上限1.0m/s；需要同事导出 R1199 训练时的命令直方图和分段时长，不可拿旧0.3m/s运行替代。
3. **动作平滑奖励不一定覆盖高频小振荡**。运行 `job.log` 有 `action_rate_l2=-0.005` 和 `teleop_target_rate=-0.12`。当前源码 `target_rate` 只惩罚超过0.18的每帧动作变化；但源码晚于训练，不能据此断言当时阈值相同。要直接记录原始ONNX动作和包装后目标的50Hz全量时序，判断波动发生在哪一层。
4. **执行器/接触差异**。训练仿真标称腿PD 55/2，实机配置也55/2，但真实电机响应、状态噪声、时延、摩擦、轮载未被证明与仿真相同。若目标平顺而实机 `q/dq/tau` 振荡，应从这些环节查起，不能盲目整体降增益。
