# S4 实机验证阶梯

前提：S0–S3 全部门槛通过（包校验/parity/sim2sim/双端构建+audit+SHA+打包）。**每一步都是独立动作，须现场人员当次明确同意**——预告不等于同意；Ctrl+C 经 Windows→HDC 不可靠，异常用 **X / 物理急停**。

## 环境前提（每次会话前只读确认）

- 狗上电、CPRO eth0 有载波、LowState ~1kHz、mode_machine=2、无残留发布端（`运行现场策略会话.ps1` 的 dry-run 会自动查）。
- 场地平整、狗趴下、现场人员握原厂遥控器与物理急停。

## 阶梯（从小到大，失败即停）

| 级 | 动作 | 观察重点 | 过关标准（范例 R1199 实测值） |
|---|---|---|---|
| **dry-run** | 只读预检全链，停在"would ReleaseMode" | 预检五项全过 | 不动狗 |
| **1. zero-B** | A 起立→B 2s 零速交接→A 回站→Y 趴下 | B 交接无单帧目标跳步、无姿态突降 | R1199 训练合同版：10ms 单帧步进 0.003rad（旧版 0.27rad）、零告警 |
| **2. 有界低速** | 同上，PolicyWalk 中单轴短推杆（如 +0.05~0.2 m/s 数秒）后松杆 | 起步无跳步、运动平顺、**松杆后姿态保持不下沉** | R1199：运动-松杆全程 thigh 稳定、保护流全零 |
| **3. 短时摇杆** | 60s 上限内自由前后（转向最后单独试） | 停/走切换无高低姿反复、可闻抖动 | R1199：旧版停走跳步已消除；抖动根因在推理侧（另案） |

每级之间：回收四份原始日志（自动归档 `field_sessions/`）、INDEX 记录现场观感 + Publisher RC + 保护位，**再单独请求下一级**。

## 诊断与分流（出问题时）

POLICY_DIAG（50Hz：raw ONNX→包装→最终目标）+ 2ms 关节流的 tick 对齐给出四段定位：

| 现象 | 定位 | 处置 |
|---|---|---|
| raw ONNX 稳态周期摆动 | 推理侧 | 回放夹具交训练侧（命令分布/动作变化惩罚/观测噪声） |
| raw 平滑、包装后目标振荡 | 包装侧 | 修包装 → 重走 parity+sim2sim+编译（=新版本） |
| 目标平滑、实际关节振荡 | 硬件侧 | 比对 PD/延迟/接触；调增益=独立候选重走门槛 |
| 发布端自停 `STARTUP FAULT: stale/invalid LowState` | 网络/负载 | CPRO 高负载下 DDS 抖动（已见例）；查负载，勿放宽 20ms 看门狗 |

工具：`tools/r1199_session_replay.py`（会话→回放夹具，可 what-if 复算）；分析范例在 `04_调试记录/logs/20261112_r1199_*` 系列。

## 实机数据录制：现状与缺项

现有 `部署测试/运行现场策略会话.ps1` 在会话完成后自动从 CPRO 拉回 `field_sessions/<时间>_<模式>/`；R1199 的会话脚本在发布端启动前开启只读监测，结束后归档。**现在已有 `-Debug` 诊断开关**，字段与实机验收状态见上文；当前 R1199 training-contract 和 R214 的现场入口已接通，新策略仍须按自身观测合同提供实际模型输入和 raw 输出，不能因为 R1199 已有 `POLICY_DIAG` 就认为新策略自动具备这些数据。下表保留为**不加 `-Debug` 的基础会话**字段说明。

| 现有文件 | 实际记录与频率 | 还缺什么 |
|---|---|---|
| `low_capture_fast.log` | R1199 当前每 2 ms 取最近一帧 LowState：tick、数据龄、IMU 四元数/角速度、35 槽 q/dq/ddq/tau_est/mode/温度；这是约 500 Hz 的**采样目标**，实际频率应以日志时间戳/包数复核 | 不含本策略最终的 Observation、内部历史/滤波、遥控原始值、独立机身速度；当前未写 IMU 加速度 |
| `low_protection.log` | 主板/电机保护状态流；独立只读监测 | 不能代替电机状态或控制指令 |
| `policy_diag.log` | **仅当前 R1199 发布端**在 PolicyHandoff/PolicyWalk/Brake 的每次控制器调用记录：命令、tick、raw ONNX、wrapped action、策略目标、站姿补偿内部量；控制器目标周期 20 ms（50 Hz） | **没有实际 65 维 ONNX 输入**；Handoff 行的目标是策略目标，尚未经 2 秒交接插值，不能当成最终发布 LowCmd；其他 FSM 状态和其他策略也未通用记录 |
| `publisher.log` / `session.log` | FSM、守卫、按键事件、预检、程序退出等文本 | 多为事件或限频输出，无法代替逐帧数据 |

**当前实机如何录：**在每次获准的动作会话中用现有 Windows 会话入口运行对应策略及模式，`MonitorSeconds` 必须覆盖等待按键、整个动作和收尾，结束后检查本地会话目录各文件是否存在、时间范围是否覆盖动作，再在 INDEX 记录现场观感和日志路径。`dry-run` 只做预检，不会生成运动期 Observation。R1199 的 2 ms 快采日志用于诊断可闻抖动；常规任务不应把它误认为模型的 50 Hz 输入帧。

### `-Debug` 诊断模式（共享发布端已实现；R1199 首次真机录制通过）

- Windows 入口 `-Debug` 向 CPRO 发布端传 `--debug`；**不改变策略、按键、速度上限、守卫或动作许可**。默认会话继续保留现有安全和事件日志，`-Debug` 增加 `debug_policy.csv` 与 `debug_lowcmd.csv`。不要把“所有数据”理解为盲录所有 DDS 话题；按该策略的观测/动作合同录全链。当前现场脚本已接入 R1199 training-contract 和 R214；新策略沿用共享发布端并在自己的会话启动器透传 `--debug`。
- 控制器每次推理（R1199 为 **50 Hz**）记录**实际送入模型的完整 Observation**、采样 tick/数据龄、原始遥控输入、滤波后的物理命令、raw 模型输出、包装后动作、策略目标与滤波后目标。R214 另记录 ONNX `state` 输入；R1199 原有 `policy_diag.log` 继续记录站姿补偿内部量。字段和单位以策略 manifest 为准，不强求所有策略有速度命令或轮速。
- FSM/发布端按最终实际发布节拍（当前发布循环 **2 ms，约 500 Hz**）记录最终 LowCmd 的 16 轴 `mode/q/dq/kp/kd/tau`、状态和 LowState tick；与独立的约 500 Hz LowState、保护流用 tick 对齐。`debug_policy.csv` 另含单调时间戳、传感器模型坐标和 IMU 加速度。这样才能区分“策略目标抖”“交接插值抖”“最终发布抖”和“目标平滑但电机反馈抖”。
- 高频 LowCmd 日志用单生产者有界队列交给独立写盘线程；会话在 ReleaseMode 前查 CPRO 余量 ≥1 GB，结束时必须确认 `dropped=0`/`file_ok=1` 并归档。不能在 2 ms 发布循环里同步逐行写文本或通过 HDC 流式输出。**ARM64 编译和离线 audit 只是代码门槛；必须先实测录制开销、丢帧率和看门狗，才能把新二进制用于有界真机试验。**

### 可选策略目标低通（独立候选，默认关闭）

Windows `-LowPassMs N`（1–200 ms）选择独立滤波构建；只在 PolicyWalk 对腿**位置目标**做一阶低通，默认**不滤轮速度**，`-LowPassWheels` 才同时滤轮速。Brake 的轮目标绕过滤波，X、Passive、FixedStand、FixSquat 不滤；增益与前馈也不滤。滤波器在 2 秒 Handoff 结束时以当前实际目标初始化。`-Debug` 可同时记录滤波前后目标。滤波改变实际控制与延迟，**即一个独立部署候选**；必须用相同滤波参数重跑离线 sim2sim、编译/audit 和有界真机门槛，不能沿用未滤波版的通过率。R1199 首测建议只滤腿目标，从 60–80 ms 做离线敏感性比较，轮速保持原链；不能把它当成训练端抖动根因已经解决。

R1199 的只读预检示例（狗未上电时会在 LowState 门槛正常退出，不会产生动作数据）：

```powershell
powershell.exe -ExecutionPolicy Bypass -File "D:\Projects\Athena\运动控制\Collie\AS2-W_CPRO\部署测试\运行现场策略会话.ps1" `
  -Policy r1199 -Mode training-contract-dry-run -MonitorSeconds 120 -Debug -LowPassMs 60
```

R1199 `-LowPassMs 0 -Debug` 首次真实 DDS 会话：26,586 条最终 LowCmd 无丢行、策略周期 p99 20.492 ms、保护位全零，现场前后滚动仍有可闻抖动；证据见 `部署测试/04_调试记录/logs/20261112-2201_r1199_debug_first_field_review.md`。之后 `-LowPassMs 40 -Debug` 分别完成15秒和30秒有界摇杆试验，现场认为前后更丝滑、转向仍很弱，保护位/软件守卫均零；详情见 INDEX 22:43 与 `logs/20261112_r1199_lp40_field_summary.txt`。当前独立 R1199 探索性入口：前后≤0.2m/s、yaw≤0.1rad/s、PolicyWalk≤30秒，轮速不滤；其他低通参数仍由 Windows/CPRO 双层锁住。0.1rad/s转向六组同合同仿真虽均直立无非轮接触，实际角速度跟踪弱；0.2rad/s曾有2/6失稳，不可直接上调。每次记录二进制SHA、滤波常数、会话目录和现场观感；Windows Ctrl+C 不是可靠运动急停，所有新实机动作仍需当次具体许可。

## 日志收集机制（当前 R1199 会话实现）

| 时机 | 谁做 | 产出 |
|---|---|---|
| 发布端启动前 | 会话脚本 step5，`nice -n 10` 拉起两个监测（`build-sdk2/as2w_sdk2`，全策略共用） | `low_capture_fast.log`（2ms 关节流 500Hz）、`low_protection.log`（保护流） |
| 运行全程 | R1199 发布端自写 | `policy_diag.log`（目标 50 Hz：raw ONNX→包装→**策略目标**→补偿内部态，tick 对齐；不含完整 Observation 或交接后的实际发布帧）、`publisher.log`（tee） |
| 发布端退出后 | 会话脚本：归档 diag + 5s 尾段 + 杀监测 | 会话目录四件套齐 |
| 会话结束 | Windows 入口自动从输出抓 `dir=` 并 `file recv` 整目录 | 工作站 `logs/field_sessions/<时间>_<模式>/` |

## 会话后

1. 当前 R1199 通常有五份日志（session/publisher/low_capture_fast/low_protection/policy_diag）在 `logs/field_sessions/<时间>_<模式>/`；逐一核大小及动作时间覆盖。其他策略可能没有 `policy_diag`。
2. INDEX 追加：现场观感、当前姿态/控制权、RC、保护位、量化对照。
3. 恢复原厂控制（`SelectMode("ai")` 可能让狗起立——本身也要当次同意）。

## 已知运维坑（实机踩过的）

- 站立保持超时：进 FixedStand 后 N 秒不按 B 自动趴下（现 30s，启动器参数）。
- 监测抢 CPU：两个监测进程必须 `nice -n 10`（防 LowState 看门狗误触发）。
- 中文路径：SSH→PowerShell 直传必炸；一切走 `C:\Users\zoubu\` 英文中转 + base64。
- HDC 掉线：`tconn 192.168.10.180:8710` 重连即可；禁 `hdc kill`/`tmode`。
- Capture 时长=MonitorSeconds 自停：慢启（趴等久）要给足秒数，否则后段没录上。
