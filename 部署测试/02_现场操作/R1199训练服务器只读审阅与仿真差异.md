## 结论先行

1. **同一权重**：训练服务器 `runs/r290-three-skills/rolling-knee-margin-formal/model_1199.pt` SHA256 为 `bb5c9735b5bd37ef4bdd2bd13f9d45395d8dc9b4c888c36955de1a345d55776d`，与本机 R1199 release 包清单一致。
2. **训练服务器自身也没有判定“可真机验收”**。对该权重的 Isaac 0.30 m/s 正式评估，前进跟踪+刹住 15/20、倒退 15/20，但前进完整跟踪+刹车+保持仅 1/20、倒退 2/20，`gate=false`。其 MuJoCo 诊断的前后/左右原地转/左右弧线各 0/1 完整通过、`gate=false`。release README 明确写 simulation preview。
3. **我的 RR_calf 触地与训练服务器的无触地诊断不是同一个实验**。两边 XML/关节默认合同哈希相同，但本项目使用真实 FixedStand 的 `q/pitch` 快照、旧 preview 近似停车/站姿控制、直接力矩 PD、不同场景种子和扰动；训练服务器使用仿真 reset 初态、其当前 parking supervisor、MuJoCo native PD、2% 丢包等。双方尚未做逐帧观测/动作/状态机完全对齐，因此不能将某个回合的接触差异归因于权重本身。
4. 本项目 seed 202 的 `RR_calf` 首次触地在滚动 1.440 s；推扰实际在 3.720 s。关闭推扰仍在 1.440 s 触地、窗口中 800 个物理子步和 50 个控制帧完全一致。详见 `R1199前进202推扰对照与视频.md`。

评估文件 `gate=false`。因此“低速能动、通常能刹住”是成立的局部结论，“可按真实手柄可靠停车并退出”尚不成立。

## 两套 MuJoCo 目前已确认的相同点和差异

相同：R1199 checkpoint SHA 一致；上游 `assets/r237-train-root/local-step-diagnostic/as2w_flat.xml` 与我方服务器 `/tmp/opencode/omni/assets/local-step-diagnostic/as2w_flat.xml` SHA 均为 `2bf148d8e0e5722db4a581c7cf7834611121025cc1c95c14f892b83bc0fdfa01`；`fall-recovery-contract.json` SHA 均为 `1e4e3fb76806e83dbe3541979fa0cb40f4b3150f5bf4de298224bf9baa9b0490`。基础 `rolling_fixed_exit()` 腿/轮动作公式也与 release 文件一致。

| 项目 | 训练服务器 release MuJoCo 诊断 | 本项目 R1199 复演 |
|---|---|---|
| 初态 | `OmniEnvironment.reset` 仿真采样，acceptance 又施加基座质量/质心与起始腿速度扰动 | 历史真机 FixedStand 腿角与 pitch −5.498°，但根高度由 MuJoCo 接触搜索，初速没有真机回放 |
| 控制执行 | `configure_native_pd` 改 MuJoCo actuator gain/bias、`implicitfast` 积分及 force clamp | 每物理子步直接算腿 `55(qcmd−q)−2dq`、轮 `2(dqcmd−dq)` 后写 `data.ctrl`；需比较执行器实际力矩时序 |
| 接管/停车 | 上游 code 使用 `rolling_precalibrated_stand`、`rolling_wheel_hold`、`parking_odometry`、`park_settle_joints`；该诊断合同还设 `park_common_gain_scale=0.5` | 旧 preview 复演器手写 stand-bias、简化轮角 hold、0.75s进入/退出 blend；没有执行 R1199 当前完整 supervisor |
| 场景 | 上游诊断种子47001等，每类1例；运动从其固定时间段开始，前进/倒退/转向/弧线全覆盖，packet loss 2%，`motion-only` 推扰 | 本轮 seed101/202/303，静止/前进/倒退各3；前后运动8s，seed202 推扰从滚动后3.72s，未模拟2%丢包 |
| 接触门槛 | 上游物理子步只要任意**非轮几何接地**就记 nonwheel，不要求力峰>1N；还检查膝部净空、站姿、轮卸载和力矩 | 我方接触计量按地面非轮法向力峰 `<1N`；seed202 首次触地24.13N，所以阈值口径差异不能解释这一次触地 |
| 停车/保持 | 上游 `stop` 需连续0.5s机身水平速度≤.025、yaw≤.06；刹车另检时间/距离；其 `held` 为停车后10s漂移、角度、速度 | 我方 `brake_ok` 除机身静稳还要求轮速<.5rad/s，最长5s；`fixed_exit_ok` 检回T2固定PD后2s关节误差<.18rad等；与上游 `held` 不是同一项 |

因此“为什么它看起来 OK、我这里不行”的准确表述是：**两个系统都没有给出完整通过；局部的跟踪/刹车率与完整门槛不同，同时我方用更接近真机的负载站姿初态暴露了右后小腿接触。** 同一 XML 不意味着同一状态机和执行器离散动力学。由于尚未逐帧对齐 obs、raw action、最终腿/轮目标、实际力矩与 q/pitch/轮载，不能进一步断言是初态、PD 积分、停车包装中的哪一项单独导致差异。
