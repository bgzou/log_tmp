## 1. 静态审查结果

逐项对照 `训练端 as2w_isaac_speed_range.py` 与 `as2w_rolling_fixed_exit.py` 的真实 `model_1199` 训练运行，`AS2W_R1199_TRAINING_CONTRACT` 分支四项均正确：

| 合同开关(真) | C++ 实现 | 训练运行 | 结论 |
|---|---|---|---|
| `park_odometry=false` | `odometry[i]=obs[22+i]`（原始轮角） | `wheel_angle = sensed[:,18:22]` | 一致 |
| `park_settle_joints=false` | `quiet_hold = max_wheel_dq<.5 && gyro<.15`，`LatchTime=0.12` | `leg_speed=None → latch_time=0.12` | 一致 |
| 无 common feedback | `clamp(-6*error[i],±1.5)/16` 逐轮 | `(-6*error).clamp(-1.5,1.5)/16` | 一致 |
| `continuous/straight=true` | `bias_scale=(1-straight)*scale + straight*upright_scale` | `scale.lerp(upright_scale, straight)` | 一致 |

其余已在旧 parity 验证的语义（`activity`、`quiet_bias`、bias 积分、`release_blend`、直行/轮 `rolling_fixed_exit`、`Side=(1,-1,1,-1)`、16 轴增益 55/2 与符号、`obs[42:58]` 回填包装后动作、轮角回绕 `wrap`）复核一致。

**发现并修复一处不匹配**：训练运行是 `wheels = wheels + hold`（叠加），旧 C++ 在锁存时用 `=` 覆盖 `rolling_fixed_exit` 轮输出。虽然旧夹具中锁存帧命令精确为零时 `wheels==0` 使旧 parity 仍通过，但该语义与训练不符，改为 `wrapped[12+i] += hold`（仅 `TRAINING_CONTRACT` 分支；旧 `#else` 分支不动）。修复后 parity 达 `1.192e-7`。

## 5b. 停走姿态跳步的 MuJoCo 复现与新旧对比（回应“FixStand→零速接管→策略回落”）

- 专写复现脚本 `logs/20261112_r1199_posture_repro.py`（无 DDS/真机）：实测 FixedStand q（thigh≈0.74/calf≈−1.79）起步，零速 6s（含 4s 偏置标定 + 锁存）→ 前进 0.05 3s → 松杆 5s，逐 20ms 记录 `q_actual/q_target/bias/hold_frames`，同权重/资产/种子，仅切换包装开关。
- **现象复现**：实测站姿被零速策略接管后整机伸展（thigh 0.74→约0.82、calf −1.79→约−1.60），与实机 0.87/−1.53 方向一致；旧分支在首次前进瞬间单帧腿目标步进 `0.124–0.127 rad @ t=4.08s`（`hold_frames` 175→0、`stand_blend` 一帧 1→0），随后大腿回落 0.82→0.78、小腿 −1.62→−1.76，对应实机 0.254/0.273 rad 首推跳步与“停走抬升/下降”。MuJoCo 偏置量约 0.13 rad（约为实机一半，仿真sag较小），故跳步幅度略小，但机制与方向完全一致。
- **新候选（continuous+straight）**：零速接管仍伸展（同零速偏置），但首次前进**无起步跳步**，单帧腿目标步进全程最大 `0.063 rad @ t≈6.5s`（正常策略控制，非起步），大腿/小腿运动段仅渐变 0.81→0.77、−1.60→−1.64。即修复消除了“策略回落”。
- 证据：`logs/20261112_r1199_posture_repro_{summary.json,report.txt,trace_{old,new}_seed{101,202,303}.json}`。
