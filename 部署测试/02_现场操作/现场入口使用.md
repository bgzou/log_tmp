# PC 上的单脚本现场入口

**2026-11-10 更新（覆盖下文 R152 时代的旧表述）：** 当前唯一 LowCmd 发布端是 `r214_publish.cpp`（CMake `AS2W_R214_PUBLISH` 默认 OFF，独立构建 `build-r214-ab-fsm`/`build-r214-zero-b`/`build-r214-ab-fsm-full` 分别限定 A-Y/B零速/全方向），已按现场逐次许可完成多轮真机验收（A/Y 三次、B 零速、行走取证，详见 `../04_调试记录/INDEX.md`）。下文"P9 R152 发布端"与"当前包没有 LowCmd 发布端"为历史表述。`Shadow` 用的 `config/hypothesis.map` 是早期假设映射；当前权威映射是 `config/r152_measured.map`（G1 实测+零位标定）。`LowRemote` 轴/键已在 P6 全量标定（A=bit8/B=bit9/X=bit10/Y=bit11，ly 前推为正，详见 `config/hardware_contract.md`）。监测阶段（LowCaptureFast/LowProtection）输出为块缓冲，按帧数/末帧时间戳判完成、达标后 pkill 回收（规则在 `../AGENTS.md`）。
在本项目根目录的 Windows PowerShell 运行：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\部署测试\现场入口.ps1 -Stage NetworkStatus
powershell.exe -ExecutionPolicy Bypass -File .\部署测试\现场入口.ps1 -Stage Sync
powershell.exe -ExecutionPolicy Bypass -File .\部署测试\现场入口.ps1 -Stage SdkBuild
powershell.exe -ExecutionPolicy Bypass -File .\部署测试\现场入口.ps1 -Stage PolicyVerify -Model all
powershell.exe -ExecutionPolicy Bypass -File .\部署测试\现场入口.ps1 -Stage GetState
powershell.exe -ExecutionPolicy Bypass -File .\部署测试\现场入口.ps1 -Stage LowState -Seconds 3
```

`NetworkStatus` 是鸿蒙宿主 `eth0` 地址、路由与 PC1 ping 的只读查询。若重启后丢失本次设置，先确认网线接在 CPRO 的 `eth0`，再执行 `-Stage NetworkApply`；其宿主脚本只补 `192.168.123.100/24` 和去往 `192.168.123.0/24` 的主路由规则，**不改默认路由**。`Sync` 从唯一源码目录重新打包、用绝对本机路径 HDC 传输、在 CPRO 校验两包 SHA-256 并解包。`SdkBuild` 校验六份模型、跑七项 CTest 并编译 ARM64 SDK2 诊断程序。

其他只读入口：`PolicyList`、`PolicyBench -Model recovery-r12 -Iterations 3000`、`SportState -Seconds 5`、`LowRemote -Seconds 5`、`LowCapture -Seconds 30`、`LowCaptureFast -Seconds 60`（100 Hz 采样，用于过渡段分析）、`MotionMode`、`ServiceList`、`PackageVersion`、`Shadow -Model stairs-r17-3000 -Seconds 60`。`LowCapture` 每 50 ms 打印一行 HG LowState 的 35 槽角度/速度（`LowCaptureFast` 为每 10 ms），离线可用 `python 部署参考/cpp_deploy-as2w/tools/analyze_low_capture.py <本机采样日志路径>` 做数值摘要。`Shadow` 是 50 Hz 只读影子链路测试：订阅 LowState、按 `config/hypothesis.map`（**假设映射，非标定**）解码、跑策略推理、仅在内存预演 LowCmd，绝不发布；每 450 tick（9 s）回合自动重臂，结束时输出 `SHADOW_SUMMARY`（tick 数、回合数、状态年龄 p50/p99/max、推理耗时 p50/p99/max）。当前固件的 `PackageVersion` 实测返回 `rc=3203`，脚本会报失败并保存原始输出；这不是 HDC 故障。`LowRemote` 打印的轴/键除左摇杆前推外尚未逐项标定。`LowCrc`（2026-11-09 新增）只读校验 LowState 的 CRC32 算法（实测 5259/5259 匹配）。**P9 发布端骨架 `r152_publish.cpp` 已入库但默认不编译**（CMake `AS2W_R152_PUBLISH` 默认 OFF）：仓库中唯一的 LowCmd 发布端，含 500 Hz writer、看门狗（状态年龄/姿态/q 键/Ctrl-C → 锁定安全 Passive，绝不裸停发）、mode_machine 逐帧回显、CRC、S2–S7 分阶段链（Passive→FixStand 插值→R152 接管→安全退出）；其运行前提（S1 释放、单关节方向验证、逐条同意）未满足，现场包绝不包含该二进制。

**R152/R41 阶段命令（历史）**：`R152Build/R152Replay/R152Shadow` 已随 R152 主线废弃仅保留兼容；当前真机主线为 R214（构建/launcher 见 `R214实机遥控与策略递进验收.md`）。

每次命令在本机 `部署测试/04_调试记录/logs/` 留一个 `*_windows_*.log`；进入 Ubuntu 的阶段也在 CPRO 工程 `field_logs/` 留原始日志。完成阶段后仍须把判断追加到 `04_调试记录/INDEX.md`，并定期用 HDC 回收 CPRO `field_logs/`。脚本检测 `field.sh` 的真实 `Exit code`；HDC 自身返回 0 不代表 Ubuntu 阶段成功。

**这个 PC 入口只覆盖只读检查、传包、编译和监测，本身不启动任何动作程序；R214 发布端经 SSH→PowerShell→hdc 调 CPRO 上的 launcher 启动（流程见 `明日bringup手册.md`），每次动作前先说清具体命令并等现场明确同意。**
