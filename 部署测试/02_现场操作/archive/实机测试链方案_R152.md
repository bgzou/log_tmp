# AS2-W R152 实机测试链方案（passive→fixstand→策略接管→遥控器行走）

2026-11-09 服务器 OpenCode 起草；执行前须逐项核对"前置门槛"。**"手柄"按用户既有决定指原厂
遥控器**（不用 Xbox/键盘）；如理解有误请现场人员指出。本文是方案，不是已批准的操作单：
S3 起每一步都是可能让狗动作的操作，**每步执行前都要单独向现场人员说明具体动作并获当次明确同意**。

## 0. 链路总览

```
开机(原厂站立) --遥控器趴下--> ai_damping
  --S1 释放运控--> 低层权限   --S2 Passive(阻尼)--> 验证不动
  --S3 FixStand 插值--> 站立   --S4 R152 接管--> 站立保持
  --S5 遥控器前推(ly)--> 慢速前进(forward_slow 域) --S6 停止/回归零指令
  --S7 退回 Passive --S8 恢复原厂运控 --S9 遥控器复核
```

任何一步异常：立即归零指令→停发→回 Passive（阻尼）→按约定转交现场人员（遥控器急停/扶持/断电）。

## 2. 零位标定路线（P2，方案待现场确认后执行）

零位同时影响**观测**（q−default）与**命令目标**（default+action），是整链的核心未决项。主方法（用户 2026-11-09 提出，**限位对比法**）：

- **A. 机械限位对比（主方法）**：趴下阻尼态，人工把每个腿关节**轻推到机械硬限位**（两端各一次，
  按固定顺序逐关节做），读 DDS 停点值，与 URDF 限位对比：
  - `zero(低端) = q_dds(下止点) − q_lo_URDF`，`zero(高端) = q_dds(上止点) − q_hi_URDF`——
    两端各自反推的 zero 应一致；
  - **斜率校验**：`(q_dds_hi − q_dds_lo) / (q_hi_URDF − q_lo_URDF) ≈ 1`（验证弧度标尺与方向）；
  - **符号校验**：往 URDF 高端推时 DDS 增/减直接检验 G1 的 sign 表。
  - URDF 限位（deploy.yaml/XML）：hip [−0.785, +0.785]×4；thigh 前 [−2.0, 3.492]、后 [−1.3, 4.19]；
    calf [−2.7677, −0.8133]×4。**注意 calf 上限 −0.8133：关节物理上永远无法完全伸直，故
    "腿伸直共线"不是可用参考位**（此点已纠正早稿）。轮无需零位（4π 回绕）。
  - 操作注意：**轻推到"扎实接触"即止，不硬怼**；每个止点保持 ~3 s、可重复 2 次取稳；
    thigh 全范围扫动若被地面/机身挡住，记录实际可达端并注明（hip/calf 双端应可达）。
  - 精度预期：止点机械重复性好，主要误差是 DDS 读数与真实停点的一致性（估计 ≤0.5°），
    远优于目视几何法。
- **B. 旁证与交叉核对**：趴下姿态 calf 读数（−2.7561~−2.7571，三腿距 URDF 下限 0.61–0.67°）
  与"折叠下止点"吻合，预期限位法下止点读数 ≈ −2.756 附近；若实测明显不同，说明趴下
  并未贴死限位，仅作记录。原厂站立读数（thigh 0.60/calf −1.23）作姿态合理性核对。
- **C. 零假设+受控单点验证（其后）**：若 A 得 zero≈0（±0.02 rad），后续 S3 前仍用**最小幅度
  位置命令**（0.05 rad、单关节、趴下低增益）验证 LowCmd 命令方向与零位假设自洽——
  LowCmd 方向与 LowState 不同源，此为 P3 项，须单独同意。

## 3. FixStand 插值设计（GO2 State_Fix 模式移植，S3 的实现）

- 模式（参考 `unitree_cpp_deploy-go2/deploy/include/FSM/State_Fix.h`）：进入时**快照当前各关节
  DDS q 为首帧**，按关键帧序列线性插值输出位置目标，结束自动转下一状态。GO2 的 12 轴数值
  与增益**不沿用**。
- 关键帧（DDS 坐标，用 G1 实测锚点）：
  - 起点 = 当前趴下读数（快照，不硬编码）
  - 终点 = **站立目标姿态**，两个候选（按 P2 结果二选一）：
    - **T1 原厂站立锚点**：hip ±0.12、thigh 0.60、calf −1.23（11:41 实测原厂站姿）——最保守，
      与原厂起立结果一致；
    - **T2 R152 默认姿态的 DDS 换算**：q_cmd = sign·q_sim + zero（需要 P2 零位）——让策略接管时
      观测最贴近训练分布。
  - 轮在插值全程发 `dq 目标 0`（速度阻尼，防溜车）。
- 时长建议 2.0–3.0 s 单段（趴下本就紧凑，无需 GO2 两段中转），插值斜率限幅、增益从低起步
  （GO2 用 60–80 kp，AS2-W 未知——**从远低值开始，先只读预演+MuJoCo 验证增益**）。
- **P8 MuJoCo 预演**：在 as2w-flat-rerun 框架里复现"趴下姿态→插值→R152 接管(state 清零)→
  forward_slow 行走"，T1/T2 两种终点各跑固定种子集；不通过不进实机。

## 5. 安全框架（每步共用的中止代码，S3 前实现）

1. **控制循环看门狗**：50 Hz 发布；LowState 年龄 >50 ms 或丢包 → 立即停发并转 Passive 阻尼。
2. **姿态保护**：up_cosine <0.8 或 base 高度 <0.20 m（跌倒判据同仿真）→ 同上。
3. **指令源保护**：遥控器数据年龄 >100 ms → 指令归零（不直接停发，先回站立保持）。
4. **单命令中止**：操作终端一个按键触发"归零→Passive"链；另有独立"停发"路径（不发任何
   LowCmd，电机自然进入失联语义——语义见 P3，未验证前不能作为首选中止）。
5. **人工路径**：现场人员遥控器急停（P5 验证后启用）→ 扶持 → 断电，事先演练顺序。
6. 所有发布端代码**默认编译关闭**（CMake 开关），不带开关绝不构建出可发布二进制。

## 8. 判据提醒（不混写验收级别）

- "跟踪/停车通过"（MuJoCo 44/52）≠ 安全通过；"严格通过"（21/52）才含接触/几何检查。
- R152 与 R41 相同判据对比：R152 固定严格 21 vs R41 13、独立 9 vs 4–5、零前轮换边 vs 18 例换边
  ——R152 全面更优；但后腿触地 ≥50 N 是两代共性，实机 S5 必须限速域并短程小步试。
- 本方案所有仿真结论限于 MuJoCo + 固定/独立两套种子；实机差异（地面、刚度、延迟）未知。
