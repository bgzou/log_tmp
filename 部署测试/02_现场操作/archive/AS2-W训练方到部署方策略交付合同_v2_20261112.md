# AS2-W 训练方 → 部署方策略交付合同 v2

> **历史版本。** 本版把滚动/行走验收要求泛化得过宽。现行交付清单为 `AS2-W训练到部署交付清单_v3_通用核心与按需模块.md`：所有策略只交最小接口核心，技能相关测试按需启用。

日期：2026-11-12。适用于 AS2-W 轮足机器人的滚动、行走、爬楼、起身等每一份新策略，以及**权重不变但观测、动作包装、增益、切换流程或配置发生变化**的修订版。训练方按本合同交付一个可独立复制的版本；部署方据此做 checkpoint/ONNX/运行包装逐帧校验、Isaac↔MuJoCo 的 sim2sim、CPRO 编译与只读影子，最后按逐次授权的短时真机门槛验收。

**一句话原则：交付单位是“训练产物 + 精确运行时 + 仿真资产 + 逐例证据”，不是单个 ONNX。** 只给权重、几张视频或服务器绝对路径，部署方无法判断真实机器人接收的动作是否与训练/评估相同。R1199 已出现真实训练运行补偿 `true/true`、实机包装 `false/false`，且曾把较早权重的运行合同错认成当前模型的合同；本规范专门阻止这两类错误。

## 1. 角色、版本和交付状态

| 事项 | 训练方交付或确认 | 部署方交付或确认 |
|---|---|---|
| 模型与算法 | 选中的训练输出 checkpoint、导出 ONNX、精确源码/配置、观测/动作/命令合同、运行包装与状态 | 独立加载、逐帧对齐、C++/ARM64 实现 |
| 仿真 | Isaac/训练环境与 MuJoCo 资产、执行器/接触参数、复跑入口、逐例结果和失败轨迹 | 用同一输入/初态/包装独立 sim2sim、报告第一处分歧 |
| 真实 AS2-W | 声明策略假设的关节顺序、单位、正方向、默认姿态、PD/轮速模式及可用域 | 用现场证据核 DDS 槽位、符号/零位、LowCmd/控制权/急停、真实初态和保护 |
| 实机结果 | 审阅部署方反馈，解释训练假设和可修改的模型/包装 | 逐次取得现场动作许可，采全程原始状态/发布/保护日志，回报问题 |

每次交付给唯一 `policy_id`（如 `as2w-rolling-rNNN-rev1`）和不可变版本号；列出来源训练 run ID、**本次实际产生的输出 checkpoint**、其初始化所用的旧 checkpoint（如果有），分别写 SHA256。`run/contract.json` 里的 `checkpoint` 常是**输入**，不可据此推断它就是最终交付权重。交付后任何权重、ONNX、源码、配置、默认参数或动作包装变更都要升版并重新出哈希与相关证据，不能沿用旧报告。

交付状态只允许明确写其中一种：`research_only`（资料未齐，可研究）、`sim2sim_candidate`（合同完整，待双仿真验收）、`hardware_candidate`（双仿真及部署离线门槛完成，待短时真机）、`field_validated`（列出已通过的**具体动作范围**）。状态不能由“训练 reward 高”“没有跌倒”“safety_gate=true”自动推导。每一速度档、运动方向、站立/停车/回退、推扰域分别列通过与未通过；已知 `gate=false` 原样保留。

## 2. 外发包必须长什么样

交付为一个可下载 ZIP/tar 包或固定 Git tag + 有 SHA 的资产包，部署方**不用登录训练服务器**即可读取以下文件。体积大的资产可给有权限、稳定、不可变的下载地址，但列文件大小、SHA256、获取命令和预期目录；不能仅给 `main` 分支或 `/root/...` 路径。包里不得含密码、令牌、设备序列号。

```text
<policy-id>/
  README.md                       # 一页结论：技能、可用/禁用域、风险、验收状态、负责人
  manifest.yaml                   # 本节与§3的机器可读总账，所有文件以相对路径引用
  SHA256SUMS.txt                  # 包内除本文件外各文件的哈希；包本身另给哈希
  provenance/
    train_run.json                # 本次实际训练作业ID/时间/源码SHA/输出权重SHA
    command.sh                    # 原样训练命令（去掉秘密，不省略参数）
    resolved_config.yaml         # 启动后解析的全部配置/开关，不是默认值列表
    source_snapshot.tar.gz        # 训练当时不可变源码；或准确commit+可获取仓库
    environment.lock             # Python/torch/Isaac/MuJoCo/驱动/容器镜像digest
    command_distribution.json    # 真实训练命令分布、速度/停走时长及采样比例
  weights/
    selected_checkpoint.pt       # 真实选中输出；若太大用可下载+SHA引用
    policy.onnx                  # 最终部署模型
    export.py                    # 确切导出命令和脚本
    parity_checkpoint_onnx.json  # 相同输入原始输出的差值
  runtime/
    observation.csv              # 每一维的来源/时序/坐标/单位/缩放/缺测规则
    command.yaml                 # 物理命令轴、遥控映射、滤波、死区、斜率、超时
    action.yaml                  # 16轴动作顺序、单位、缩放、偏置、限幅、轮速语义
    wrapper/                     # 完整后处理、停车/站姿补偿、历史/相位、所有依赖
    resolved_flags_train.json    # 训练时真正生效的包装开关
    resolved_flags_isaac.json    # 正式 Isaac 验收时生效的开关
    resolved_flags_mujoco.json   # 正式 MuJoCo 验收时生效的开关
    state_machine.yaml           # 可进入/退出姿态和切换状态、时序及复位规则
    gains_limits.yaml            # 每个状态、每个轴的目标/增益/力矩与软硬限制
  simulation/
    assets.sha256                # URDF/XML/mesh/碰撞体/地面/执行器资产哈希
    isaac/                       # 可运行脚本、锁定配置、种子及逐例结果
    mujoco/                      # 与 Isaac 一样，不能只有最终汇总
    cross_sim_diff.md            # 同一权重/命令/初态的两仿真器差异
  replay/
    cases.json                   # 零速、前后、转向、停走、退出等固定输入说明
    frames.npz                   # 每帧观测+状态+命令+上一动作+原始/包装动作
    expected_targets.csv         # 最终16轴q/dq/kp/kd/tau、包装内部状态
    compare.py                   # 部署方可复算，输出首个不一致帧及最大误差
  handoff.md                     # 双方责任、未解决项、版本冻结与签收记录
```

确实不适用的字段写 `not_applicable` **并说明原因**；未采集写 `missing`、责任人和计划，不允许留空、`TODO`、用“见代码”代替。`missing` 不得被包装成已通过门槛。必须给一条从 `manifest.yaml` 到**真实训练输出 checkpoint**、ONNX、包装源码和正式评估的可追踪链；外发包 ZIP 的 SHA256 作为**包外随附校验值**交付（避免包内自引用哈希）。不能只用相似文件名认版本。训练服务器当前源码如果训练完成后被修改，必须提供训练时源码快照；空 `git/` 目录不算快照。

## 3. manifest 中必须有的具体字段

以下是**填写结构示意**，尖括号必须替换成实值或文件相对路径。训练/Isaac/MuJoCo/部署四处参数差异另给逐字段对照表，标明每一差异是否故意、由谁批准、影响哪些场景。

```yaml
schema_version: 2
policy_id: <唯一版本>
skill: <rolling|walking|stairs|recovery|...>
delivery_status: <research_only|sim2sim_candidate|hardware_candidate|field_validated>
created_at: <日期与时区>

train_run:
  id: <本次实际运行ID>
  source_snapshot: provenance/source_snapshot.tar.gz
  command: provenance/command.sh

  output_checkpoint: {path: weights/selected_checkpoint.pt, sha256: <值>}
  initialization_checkpoint: {path_or_not_applicable: <值>, sha256: <值>}
  training_commands: provenance/command_distribution.json
model:
  onnx: {path: weights/policy.onnx, sha256: <值>, opset: <值>}
  runtime_tested: {name: onnxruntime, version: <版本>, architecture: [x86_64, aarch64]}
  inputs: [{name: <实际名>, shape: <如[1,65]>, dtype: float32}]
  outputs: [{name: <实际名>, shape: <如[1,16]>, dtype: float32}]

  command: runtime/command.yaml
  action: runtime/action.yaml
```

模型还须注明：动态/固定 batch，ONNX external data 文件、算子/自定义算子、输入输出名称与维度、float32/float16、是否递归/带 hidden state、控制频率、推理耗时分位数和超时处理。要证明 checkpoint→ONNX 的**原始输出**一致；还要独立证明部署实现的**最终电机目标**一致，二者不是同一个测试。

## 4. 训练方必须写到逐字段的运行合同

### 4.1 观测：模型实际吃到什么

`runtime/observation.csv` 每行至少：`start_index,end_index,name,source,frame,unit,sign,scale,offset,clip,filter,update_hz,age_limit_ms,missing_fallback,reset_rule`。向量维度必须恰好覆盖模型输入，不重叠、不缺洞；历史堆叠每一帧的顺序、时间间隔、warm-up 伪数据与清零时机写明。特别逐项说明：

- IMU 四元数顺序、投影重力和角速度的机体系/世界系；轴正方向；是否使用机身速度真值、轮端运动学估速或学习估计，实机没有的训练特权信息如何替代。
- 16关节位置/速度的策略顺序、相对默认角还是原始编码器、轮角回绕区间/记忆更新、关节零位偏差、编码器/速度滤波、每帧数据龄和丢包时保持/复位。
- 上一动作到底是**ONNX 原始输出**、裁剪后动作、包装后动作，还是最终受限电机目标；状态机切换前后的历史/相位/积分器怎样复位。历史反馈用错会让 sim2sim 结果失效。
- 明确每项是否可从当前 AS2-W LowState/其他已验证 DDS 源得到。真实机器人没有的量必须标 `requires_estimator` 并给估计器源码、误差验证和降级策略，不能默认为可用。

### 4.2 命令：遥控器和物理量的合同

列出支持 `vx/vy/wz` 哪些轴（不支持的轴必须写 `ignored`）、物理单位、机体系、正方向、最大/最小**训练**值、部署请求上限、摇杆轴与按键对应、死区、归一化、限幅、滤波、加减速斜率、命令龄与超时、零速保持/制动定义。**指令限幅不等于真实机身速度硬限**。训练命令直方图须统计零速比例、0–0.05/0.05–0.1等低速区间、方向、持续时间、反向/松杆次数；若实机预期用细推而训练几乎没有这种片段，必须在 README 首段标风险。轮式策略的“松杆”是请求速度零、进入刹车状态还是锁轮，必须写明停车距离/时间的验收标准。

### 4.3 原始动作 → 最终16轴目标

`runtime/action.yaml` 和 `wrapper/` 要提供**按调用顺序**的完整公式/源码与参数：原始输出裁剪→动作缩放/默认角→轮速度/轮角目标→站姿/重力/停车补偿→滤波/斜率→限位→PD/前馈→输出。每个中间状态（例如站姿 `bias`、轮角 reference、`hold_frames`、上一动作、相位、历史窗口）写初始化、更新、冻结、松杆、重入、退出规则。训练、正式 Isaac、正式 MuJoCo、部署拟用开关分别给**解析后的实值**；布尔字段尤其不能只给代码默认值。每个不同开关组合是不同运行时版本，即使 ONNX SHA 一样也要重做最终目标 parity 与仿真。

16轴逐项写策略关节名、sim正方向、单位、`q/dq/tau` 中哪些量输出、腿/轮控制模式、默认目标、缩放、偏置、限幅、速度/位置跳变限制。`runtime/gains_limits.yaml` 还应逐状态给 `FixStand/PolicyHandoff/PolicyWalk/Brake/ReturnStand/FixSquat/Passive` 等实际使用状态的每轴 `kp/kd/tau_ff`、切换插值与退出条件。不同策略、不同状态可以用不同增益，**不存在跨策略默认55/2**；若某增益是部署方选择而非训练方验证，必须在差异表中标为“待验收”。真实 DDS 槽位/符号/零位由部署方以现场 `hardware_contract.md` 核定，训练方不得从 Go2/As2 等机器人推断填入。

## 5. 仿真资产与 sim2sim 必交证据

训练方交付两套**可从包内或固定依赖恢复**的 Isaac/MuJoCo 运行入口。每个运行脚本一条命令能重跑，写明容器/依赖版本、物理步与控制步、URDF/XML/mesh/碰撞体 SHA、几何和质量/惯量、轮地摩擦、执行器模型、腿/轮 PD、饱和/延迟/通讯噪声、随机化域、推扰时刻/强度、随机种子。原始训练资产、正式评估资产和部署方使用资产若不同，逐项列差异；不要把诊断脚本称为正式验收。

**先做完全相同的输入/输出回放，再比闭环。** `replay/` 至少覆盖：零速启动、持续前进/后退、松杆停车、反向、低速细推、姿态/历史复位、动作切换、正常退出；支持转向/侧移的策略也覆盖相应轴。每帧同时保存 `timestamp,观测65维(或本策略实际维度),物理命令,ONNX原始动作,每层包装动作,最后16轴q/dq/kp/kd/tau,下一帧上一动作观测`；报告 checkpoint↔ONNX、训练 Python↔部署 C++、Isaac↔MuJoCo 的最大误差、最差轴/帧及**第一处分歧**，阈值在评估前按数值精度约定。只给 raw ONNX parity 不算完成。

闭环至少包括这些路线，均从**相同的根姿态、16轴q/dq、历史状态和命令**起步：

| 路线 | 要看什么 | 必须输出什么 |
|---|---|---|
| 固定站姿→策略零速接管 | 接管目标跳步、下沉、轮载、姿态 | 前后各至少2s的目标/实测曲线、16轴峰值 |
| 小幅前进/后退→松杆→驻停 | 低速跟踪、运动中振荡、刹车及额外位移 | 每轴q/dq/tau、目标变化、机身速度/高度、四轮载荷 |
| 反向、转向/弧线（若支持） | 方向符号、横漂、左右不对称 | 每方向独立通过率与失败轨迹 |
| Brake→ReturnStand→FixSquat | 出口连续性、实际站姿误差、受控趴下 | 阶段边界全量曲线、非轮接触首时/部位/峰值 |
| 观测延迟/丢帧、推扰/摩擦变化 | 鲁棒性和保护动作 | 有扰/无扰、单因素/组合结果，不能只给最好视频 |

对每个用例保存**逐例**结果而非仅平均值：种子、初态、实际命令、场景与资产SHA、是否跟踪、是否能停住、非轮接触**首次时间/部件/法向力及持续时间**、四轮离地/载荷、最大目标步进、关节速度/力矩、车身俯仰/高度、跌倒、刹车距离/时间、退出后位置误差。失败样例要保留时序/视频或可重渲染状态。给清楚分母，如 `前进跟踪15/20、完整退出1/20`；“无跌倒”不能替代“完整链通过”。安全门槛与完整技能门槛分列。阈值由策略/场景在试验前写入合同，并标明来源；`0.18rad`、`50N`等某次诊断值不可当宇树官方通用标准。

训练方应接收部署方给出的**实测 A 键 FixedStand q/dq/quat 与低层增益**，做一组单独标记的“实测初态”仿真。若训练方用理想 T2 起步、部署方用真实有负载偏差的站姿起步，必须同时报告两组，不能把理想组的通过率当作上狗结果。若仿真无法建模电机内环声音、高频电流或真实摩擦，明确其可证明和不能证明的范围。

**运动抖动与停走姿态要分开验收。** 对持续匀速段，排除起步/停车边界后逐轴报告原始动作、包装目标、实际 `q/dq/tau` 的 RMS、峰值、连续正负交替片段及可解析频带的谱；同时给静止对照。对 `零速→小幅前进→松杆→小幅后退→松杆`，记录每 20 ms 补偿/停车内部系数、最终目标最大单帧跳步、站姿高度/俯仰变化和松杆后位移。用户听到的声音属于实机观测；100 Hz LowState 或 MuJoCo 无法单独确认声源，必要时同步录音/高频电流。不能因为无跌倒或硬件保护位为零，就把可闻抖动记为“通过”。允许的 RMS/峰值/停走姿态变化由该策略在评估前约定并附来源，不从另一版复制。

## 6. 正常切换和故障切换合同

训练方必须写 `state_machine.yaml`：允许的入口姿态/角误差/速度/直立条件，策略启动时历史、轮角参考、站姿补偿、相位如何初始化；接管首帧和全量100%后首0.5s如何限制目标跳变；摇杆松开后是继续策略零速平衡还是固定 PD 站；从任何运动阶段如何刹轮、冻结/插值回固定站、再受控趴下；各阶段超时、遥控失联、反馈失鲜、姿态越界、力矩/速度保护时的安全处置。说明退出**可保证什么**，以及未验证的状态边。

部署方把上述语义映射到已验证 AS2-W 控制权与 LowCmd 序列。训练方不负责猜固件 `ReleaseMode/SelectMode` 行为，但若策略假设“直接退控仍能站立”“零命令一定不动”“遥控器急停在低层有效”，必须明确标为**待现场验证的前提**。高层原厂控制恢复可能改变姿态，不能当作无动作清理命令。

每次真机试验回传至少：政策/包装/增益/二进制SHA，完整发布端原始日志、LowState和保护流、用户现场观感、实际动作时长/方向/停止过程、异常视频/音频（如有）和调试日志索引。训练方据此修复后重新交付新版本，不能让部署方从聊天截图猜出“这是起身还是盲走、支持vy吗、零速会不会滑、增益用多少”。
