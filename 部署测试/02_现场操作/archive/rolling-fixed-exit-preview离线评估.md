# rolling-fixed-exit-preview 离线评估

日期：2026-11-11。结论适用于 Rob2Nav main 提交 `7bae69bbf682a741339b24dfa66b477fd3890b01` 的
`deliveries/as2w-deploy/rolling-fixed-exit-preview`。本阶段只有 GitHub 资料审计、ONNX 离线推理和服务器
MuJoCo；没有连接机器人控制权、没有发布 LowCmd、没有同步或解锁任何真机 launcher。

## 结论

**当前 preview 不通过地面真机测试门槛，不绑定 B，不复用 R214/R284 launcher 直接测试。**

原因不是“模型不能滚”：理想条件下前后滚动能够跟踪，静态零速也能站住；失败点是完整链路的鲁棒性和退出：

1. 上游自己给出的 MuJoCo acceptance 为 `gate=false`，120 个场景仅 forward 1 个完整通过，其余方向均 0。
2. 本项目独立压力复演也为 0 个完整通过：随机质量/摩擦/增益和推扰下出现横漂、转向倾倒/非轮接触，且
   `Policy→FixedStand` 的最终腿误差门槛在所有场景均失败。
3. 从真机历史 FixedStand 实测状态（而非理想 T2）注入后，零速站立仍稳定，但 B 接管阶段腿速度峰约
   `2.57–2.59 rad/s`；前后滚动横漂明显，退出门槛仍 0/3。该状态注入不是完整真机动力学复刻，但它是风险证据，
   不能被理想初态结果覆盖。
4. R284 已证明理想 MuJoCo 可能给出假阴性；本策略现在连自己的双仿真门槛都未通过，更不能以“小速度试一下”
   代替离线闭环验收。

## 模型和命令合同

- ONNX：`obs[1,65] → actions[1,16]`，50 Hz；SHA-256
  `4d8e7bcfcbebdd107765535d074a79acc7519d6734850d285fa978d4670b4afa`。
- checkpoint 1199 SHA-256：
  `e66a1bbac8cdae8cadf1d7c58226c1ac99178ad4b4a1ac7e98dbc334256caadc`。
- 上游 recorded-observation parity：7523 帧，最大动作误差 `1.91e-6`；只能证明 ONNX 导出一致。
- 命令三元组语义是 `[vx, vy, wz]`。观测中的静止值 `[-0.4,0,0]` 来自 `vx-0.4` 的归一化/中心偏移，
  **不代表静止时发送 −0.4 m/s**。
- 执行包装 `rolling_fixed_exit()` 只读取 `vx` 和 `wz`，完全不使用 `vy`。独立 `vy=0.10` 探针的实际
  `vy≈0.00008 m/s`，所以该策略**不支持侧移**，现场必须永久把 `vy` 锁为 0。
- 上游速度评估的平移上限是 `|vx|≤0.30 m/s`，转向报告测试到 `|wz|=0.30 rad/s`。这只是训练/评估域，
  不是首轮真机建议值。
- 零命令时动作包装把腿残差和轮速都门控回固定站/零轮速；这解释了静态表现好于 R249/R270，但不解决
  真实 FixedStand 初态、受扰运动和退出门槛。

### 真机 FixedStand 实测状态注入

初态采用历史稳定窗：hip `[-0.221,+0.217,−0.270,+0.264]`、thigh
`[0.746,0.743,0.708,0.713]`、calf `[−1.720,−1.731,−1.863,−1.869]` rad，pitch `−5.498°`；
而控制端仍持有 T2 命令，模拟现实 B 前“命令是 T2、反馈不是 T2”。

| 场景 | 稳定 | 跟踪合格 | 回 FixedStand | 主要现象 |
|---|---:|---:|---:|---|
| measured static | 3/3 | 3/3 | 0/3 | 零速能站，B 进入时腿速度峰约 2.57 rad/s |
| measured forward 0.30 | 3/3 | 0/3 | 0/3 | 平均 `(0.266,−0.135,−0.092)` |
| measured back −0.30 | 3/3 | 0/3 | 0/3 | 平均 `(−0.227,+0.164,−0.091)` |

状态注入没有真实电机延迟/柔顺，`2.6 rad/s` 不能直接预测真机数值；但足以否定“FixStand 已等于模型默认姿态、
可按理想 T2 无缝切换”的假设。

## 后续门槛和未来操作语义

当前不开发/同步真机发布端。要重新评估，至少要求上游或本项目修订版满足：

1. 明确每策略腿/轮 `kp/kd` 与训练执行器合同，不能默认复用 55/2。
2. 用真机 FixedStand 实测 q/quat 初态做静止、前后滚动、刹停、退出压力复演；FixedStand gate 应与真实可达误差一致，
   或采用补偿后的 PolicyReadyStand/冻结策略腿目标，不能简单放宽门槛掩盖问题。
3. forward/back、静止、刹停和退出分别达到固定随机集全通过；转向未修复前 `wz` 必须锁 0；`vy` 永久锁 0。
4. 通过 ONNX Runtime 1.22 C++ 回放、x86/ARM64 构建、offline-audit，再讨论支架离地的有界 zero-B；地面运动另行申请。
5. 若未来达到首测门槛，按键仍建议 A=FixedStand、B=策略；首测只开放 `vx=+0.05 m/s`、1–2 s 自动刹停，
   `vy=wz=0`，然后回 PolicyReadyStand。每次动作仍须现场人员当次明确同意。
