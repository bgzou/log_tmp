## 3. 下次测试操作流程

**前提**：狗上电趴好（原厂趴下即可）；现场握原厂遥控器+物理急停；每步当次告知同意。
WiFi 目标 192.168.10.180:8710 视状态可用则用 WiFi，否则 USB `-t 0123456789ABCDEF`。

**Step 0（可选，只读）**：dry-run 确认链路——
```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\zoubu\as2w_session.ps1" -Policy getup1199 -Mode getup-dry-run -MonitorSeconds 60 -Target 0123456789ABCDEF
```
预期：step1 audit PASS、step2 LowState ≥100 包/s、step3 停在 factory/released 提示（dry-run 设计如此）。

**Step 1：正式会话**——
```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\zoubu\as2w_session.ps1" -Policy getup1199 -Mode getup -MonitorSeconds 150 -Target 0123456789ABCDEF -ConfirmMotion
```
等待输出 `STARTUP: Passive ready`（约 3-5 秒）→ **按一次 B**。

**预期日志顺序**（每个都是通过信号）：
```
[Passive] → FixCrouchLite (B; knee-open 2.5s)     ← B + 入口门通过（Y趴姿不在包络，走开膝）
[FixCrouchLite] envelope reached → PolicyGetup    ← 开膝后包络复检通过（这次会真的动）
GETUP_GATE h_est=... up=... jerr=... hold=...     ← 每 0.2s 打一次，起身段看 h_est 爬升
[PolicyGetup] → FixedStand (success; hold=100 frames h_est=0.3x)
GETUP TRIAL: prone hold complete, stop            ← Y/30s 自动趴下后会话干净退出
```
**现场预期**：开膝 2.5s（机身抬约 3cm，几乎不动）→ 起身 3-5s（大幅动作）→ 站立保持（h≈0.31-0.38m）
→ 按Y或30秒自动趴下。X 随时急停；一个会话只按一次 B。

**失败分流**：
- `[Passive] B rejected: entry gate ...` → 看打印的 h_est/up/wheel_dq：趴姿异常或狗不在趴地。
- `[FixCrouchLite] envelope NOT reached` → 开膝后小腿仍在包络外（若狗这次真动了但没到 −2.43，
  检查腿是否被卡）。
- `GETUP_TRIAL: B not pressed in 120s` → 120 秒没按 B（下次注意：ready 后有 120 秒窗口）。
- `FIELD_GETUP_TIMEOUT` → 起身 15 秒未达成功门，自动回 Passive（安全停，无动作风险升级）。
- 任何 `FIELD_SAFETY_HARD ... invalid=1` 首帧单次 → 已知良性（首帧无 previous 目标）；
  若连续出现并伴随 `→ EmergencyDamping` → 真触发，停下分析。
