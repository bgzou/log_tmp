# AS2-W 一键现场会话与策略切换指南

更新：2026-11-11（新增 §2.1 R214 最小安全壳日志判读）。本文是个人 Windows PC、工作站和 CPRO 之间的一键现场入口权威说明。具体策略的模型合同、增益和限制仍以该策略目录及 `04_调试记录/INDEX.md` 最新记录为准。

> **当前可用范围（2026-11-10晚）**：Windows入口只注册`r214`。`dry-run`为纯检查；`stand`与`zero-b`已真机通过；`motion`可启动但R214持续行走会后腿下沉，只允许受监督的极短链路诊断，不是可用行走方案。R284在真机全策略接管时发生剧烈振荡，Windows未注册且CPRO的field-session/zero-B两个入口均已无条件FATAL阻断；R249/R270也未注册、不得真机运行。

## 1. 调用链和入口

```text
个人 Windows PC / 工作站
  运行现场策略会话.ps1
    -> HDC WiFi 192.168.10.180:8710
      -> CPRO /root/as2w_deploy/tools/run_<policy>_field_session.sh
        -> 前置门槛 + 监测 + 对应发布端
```

个人 PC 和工作站是同一套 Windows 入口；命令使用绝对路径，因此可在任意 PowerShell 目录执行。当前入口只注册 `r214`，以后增加策略时扩展 `-Policy` 枚举和 CPRO profile，不复制安全检查。

只读演练：

```powershell
powershell.exe -ExecutionPolicy Bypass -File "D:\Projects\Athena\运动控制\Collie\AS2-W_CPRO\部署测试\运行现场策略会话.ps1" -Policy r214 -Mode dry-run -MonitorSeconds 30
```

会动作的通用格式（每次必须先完成当次动作审查和现场明确同意）：

```powershell
powershell.exe -ExecutionPolicy Bypass -File "D:\Projects\Athena\运动控制\Collie\AS2-W_CPRO\部署测试\运行现场策略会话.ps1" -Policy r214 -Mode <stand|zero-b|motion> -MonitorSeconds <60..300> -ConfirmMotion
```

## 2. Mode 的含义

| Mode | 发布端能力 | 当前用途 |
| --- | --- | --- |
| `dry-run` | 不 ReleaseMode、不发 LowCmd | 检查 HDC、DDS、模型、二进制和控制权 |
| `stand` | A 起立、Y 趴下；B 编译锁 | 验收安全启动、FixStand/FixSquat；2026-11-10 一键实机通过 |
| `zero-b` | A 起立、B 进入策略但摇杆强制零、自动回站/Y | 新策略首次接管的有界门槛 |
| `motion` | A/B/Y/X 和摇杆速度映射 | 仅在 stand/zero-b 通过后做短时运动；策略自身缺陷仍可能出现 |

`-MonitorSeconds` 是保护与 LowState 采样的最长时长，不是策略动作持续时间。发布端先结束时，CPRO 仍会等待监测计时结束，再打印 `session complete` 并由 Windows 自动拉档。因此动作做完后终端看似等待是正常的。

## 2.1 R214 最小安全壳：启动横幅与运行中日志判读（2026-11-11）

R214 发布端（`build-r214-ab-fsm*` / `build-r214-zero-b`）在 `GO` 确认前打印一行 `FIELD_SAFETY_PROFILE`。**启动时必须看到这一行**；缺行说明运行的二进制不是当前安全壳版本，应先停下核对源码/二进制 SHA256 再继续。该行内容：

```text
FIELD_SAFETY_PROFILE command_accel=0.2,0.1,0.2 command_decel=0.4,0.2,0.4
  remote_timeout_ms=200 leg_dq=5/8 wheel_dq=8/12 leg_tau=35/50 wheel_tau=8/12
  leg_pd=35/50 wheel_pd=8/15 leg_step=0.2/0.35 wheel_step=15/30
  warn_frames=5 hard_frames=3 (units: dq rad/s, tau/pd Nm, step per 20 ms)
```

- `command_accel/decel`：`vx/vy/wz` 三轴加/减速度限幅（进入满量程约 0.5 s，回零约 0.25 s）。
- `leg_dq` 等八组都是 `warning/hard` 两档；`warn_frames/hard_frames` 是连续命中帧数（50 Hz）。
- 守卫只在 PolicyHandoff/PolicyWalk/Brake 生效，不影响已验收的 FixStand/FixSquat。

运行中日志行的含义：

| 日志行 | 含义 | 发布端动作 |
| --- | --- | --- |
| `WALK_CMD vx/vy/wz=… requested=… ly/lx/rx=…` | 每 0.2 s 一条；`vx/vy/wz` 是**整形后实际发给策略的命令**（applied），`requested` 是摇杆原始映射值。两者长时间不一致且 requested 非零，说明存在超时/有界试验/时限强制归零 | 无 |
| `FIELD_SAFETY_WARN/HARD state=… count=…` | 守卫指标越 warning/hard 档，`count` 为连续帧计数；首帧、达标帧及之后每 25 个 warning 帧限频打印 | 无（仅记录） |
| `FIELD_SAFETY_SOFT_TRIP state=… count=5` | warning 连续 5 帧 | 受控 `Brake`（goal=FixedStand） |
| `[状态] → EmergencyDamping (field hard limit)` | hard 连续 3 帧或任一有效轴 `motorstate != 0` | EmergencyDamping（站立时可能下沉，见 §3.5） |
| `REMOTE_TIMEOUT age_ms=… → controlled Brake` | 200 ms 内没有格式合法的遥控 payload（头 `55 51`、轴值有限且 |值|≤1.5） | 受控 `Brake`；恢复后**不会自动重新进入 PolicyWalk**，需回站后重新过 B 门槛 |

判读要点：`leg_tau/wheel_tau` 是 LowState 实测 `tau_est`，`leg_pd/wheel_pd` 是按 `kp*(q_cmd-q)+kd*(dq_cmd-dq)` 预计的 PD 力矩——`LowCmd.tau=0` 不代表没有电机力矩；`leg_step/wheel_step` 是相邻 50 Hz 帧的目标跳变。触发任何守卫后，先按 `04_调试记录` 提取完整时间线解释原因（模型输出、包装、真实反馈还是阈值过窄），不要直接放宽阈值。

已知限制：HG 内嵌 40 字节遥控 payload 没有可见 sequence/timestamp。如果固件持续重复一帧“格式合法但陈旧”的 payload，发布端无法把它与用户保持摇杆不动区分，当前实现不是完整链路失联检测。

会话与退出规则（对 §3.4/§3.5 的通用化）：

- `Ctrl+C`（SIGINT/SIGTERM）是**操作员结束会话**：发布端清理并停发 LowCmd。站立时停发仍可能因重力下沉，优先按 Y 受控趴下、等 `publisher rc=0` 后再退出；运动中若要立即制动，顺序是 A 回站（仍可控时）→ X 阻尼 → 物理急停，不要把 Ctrl+C 当运动中的急停。
- 会话目录（CPRO `/root/field_sessions/<时间戳>_<mode>/` 与 Windows transcript）**必须拉回本机 `04_调试记录/logs/`**，不能只留在 CPRO；一键脚本会自动拉档，手动会话须人工回收。
- 本节阈值是 R214 低速早期 bring-up 档（依据 R214 trace 分位数与 R284 事故峰值设定），**不是所有策略共享的永久常量**：后续 B、L1+B 等策略各自拥有策略合同与 safety profile，共用的是守卫机制（连续帧计数、两级阈值、超时 Brake、EmergencyDamping 退路）本身。

## 3. R214 Motion 一次最小链路测试

### 3.1 已知边界

- R214 零速接管已经实机通过，但持续平地行走会出现后腿逐渐下沉；这次只验证链路，不评价策略质量。
- 只测约 1 秒、`0.03–0.05 m/s` 的轻微前进；不测侧移、转向、后退，不把摇杆推到底。
- A 回站曾多次实机恢复；仍不能把它当作物理急停。X 会进入阻尼，站立时可能下沉；物理急停是最终手段。
- B 接受时要求摇杆居中、固定站至少0.5秒、姿态/轮速/静止门槛通过。B 被拒绝时不要连按。

### 3.2 执行前检查

1. 狗稳定趴下，四周至少留出前方约2米、两侧约1米空地。
2. 现场人员握原厂遥控器，能立即按 X 和物理急停；人员不要站在狗正前后。
3. CPRO→狗网线稳定，Windows HDC target 为 `192.168.10.180:8710`（直连；旧 `10178` 中继已停用）。
4. 上一会话已经看到 `publisher exited rc=0`；若没有，先只读检查远端进程，不能叠加启动。
5. 对本次“起立→B接管→轻推前进1秒→A回站→Y趴下”取得明确同意。

### 3.3 Motion 命令

只有在 3.2 全部满足并获得当次同意后运行：

```powershell
powershell.exe -ExecutionPolicy Bypass -File "D:\Projects\Athena\运动控制\Collie\AS2-W_CPRO\部署测试\运行现场策略会话.ps1" -Policy r214 -Mode motion -MonitorSeconds 90 -ConfirmMotion
```

### 3.4 屏幕和遥控器操作顺序

1. 脚本自动完成 audit、LowState、控制权、ReleaseMode、16轴mode0和双监测。任一步 `FATAL` 都停止，不继续按键。
2. 等到 `STARTUP: Passive ready after ... frames`。先不要按键，原地听和观察5秒；有嗡鸣、报警或抖动就按X/急停并停止。
3. 短按并松开 A 一次。等待屏幕依次出现：

   ```text
   [Passive] -> FixStand (A)
   [FixStand] -> FixedStand (PD hold; B required for R214)
   ```

4. 确认狗固定站稳；所有摇杆完全居中。短按并松开 B 一次。等待：

   ```text
   [FixedStand] -> PolicyHandoff (B accepted: ...)
   [PolicyHandoff] -> PolicyWalk (zero-speed handoff complete)
   ```

   若打印 B rejected，停止反复按键，直接按Y趴下并检查门槛日志。

5. 进入 PolicyWalk 后仍保持摇杆居中约2秒，观察后腿是否开始下降。若下降，立即按A回站，不做移动。
6. 若稳定，左摇杆轻推向前约四分之一行程，持续约1秒后完全松开。目标只是看到轮子和机身有可控前进响应，绝不推满。
7. 松杆后立即短按 A 一次。等待：

   ```text
   [PolicyWalk] -> Brake (A)
   [Brake] -> ReturnStand (A/timeout, wheels stable)
   [ReturnStand] -> FixedStand
   ```

8. 确认固定站稳，短按 Y 一次。等待 FixSquat→Passive、`MOTION_TRIAL_REMOTE_RC=0` 和 `publisher exited rc=0`。
9. 不急着按 Ctrl+C。等待监测结束、`session complete`、`Local session archive: ...`。若 publisher 已RC0但HDC尾部长期不退出，Ctrl+C不会再影响LowCmd，但会中断自动拉档，需要人工拉回。

### 3.5 中止与通过标准

立即中止：嗡鸣/喇叭报警、明显失稳、后腿快速下沉、非轮部件触地、运动方向相反、无法停止或无法回站。优先顺序：A回站（仍可控时）→X阻尼→物理急停。`Ctrl+C` 不是运动中的急停手段。

通过最低标准：启动无报警；A起立稳定；B只触发一次且完成交接；轻推前进方向正确；松杆+A后轮速下降并回固定站；Y平顺趴下；发布端RC0；保护日志 `warning_or=0`、`motorstate_or=0`。通过仅证明现场链路，不代表R214运动质量合格。

## 4. 日志和乱码

- CPRO：`/root/field_sessions/<时间戳>_<mode>/`。
- Windows transcript：`部署测试/04_调试记录/logs/<时间戳>_windows_<policy>_<mode>_field_session.log`。
- Windows 自动拉档：`部署测试/04_调试记录/logs/field_sessions/<时间戳>_<mode>/`。
- `鈫?` 是 Windows PowerShell 5.1/hdc 把 UTF-8 箭头 `→` 解码错误，只影响显示，不影响状态机和命令。后续源码日志应逐步改为 ASCII `->`。
- 每次成功、失败或中止都要把现场观察、命令、RC和日志路径追加到 `04_调试记录/INDEX.md`。

## 5. 策略、FSM 状态和增益原则

- 增益不是全项目统一常量。FixStand、FixedStand、PolicyHandoff、各 Policy、FixSquat、Passive 可以有不同 kp/kd；每个新策略也可能不同。
- 策略交付必须明确自己的观测、动作缩放、腿/轮 kp/kd、命令范围、后处理和历史状态。当前 R214 的策略值不能复制给未来策略。
- A/固定站和Y/趴下属于机器人FSM状态参数；B、未来的 `L1+B` 等组合键可绑定不同策略 profile，各自读取模型与增益配置，并分别走 replay/audit/MuJoCo/zero-b/真机有界门槛。
- 新策略替换顺序：模型合同与命令域→只读shadow→离线audit/编译→MuJoCo关键路线→有界zero-b→短时motion。不能只替换ONNX文件。
- 当前 R249 因零速度仿真出现明显非零轮速和0.15–0.75m位移，禁止落地按B，等待训练侧修正；不影响R214一键脚本本身。
- 当前 R270-preview 同样未过零速门槛：上游 stop 评估 0/8 保持，独立三种子零速3秒位移0.42–0.44m；且交付未明确策略 kp/kd。它尚未注册到 Windows `-Policy` 或 CPRO profile，禁止用替换 ONNX 的方式绑定 B。
- R284-500 的离线MuJoCo曾通过，但真机全策略接管后发生剧烈振荡，证明该仿真门槛出现假阴性。当前R284所有真机入口均硬阻断，禁止zero-B和motion；不得手工绕过或复制二进制直接启动。
