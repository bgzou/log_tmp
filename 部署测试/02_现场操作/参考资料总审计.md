## 策略与真机状态

同事交付的是**两类技能、六份权重**：恢复 `r09/r12/r13` 和盲爬楼 `r14/r17-2000/r17-3000`。其原生 MuJoCo 报告显示恢复 r09、r13 为 16/16，r12 为 15/16；三份爬楼均为 **0/16**。这是交付报告的结果，不是本机重新跑出的仿真结果；60 帧 fixture 通过只证明推理数值复现。明天不把任何一份爬楼权重列为真实楼梯测试候选。

训练控制合同：每 20 ms 一次，58 维观测、16 维输出；模型轴顺序与 DDS 顺序分离；恢复需要机体系线速度且开始约 2 秒为被动阶段，盲爬楼的前向指令固定为 0.4 m/s。原厂遥控器可用于原厂运动以及未来技能使能/停机输入，但不能直接给这两类模型调速。离线基准必须在 CPRO 上重跑；个人 PC 的耗时不证明 CPRO 达标。

## 最终迁移架构与实际顺序

`CPRO Ubuntu → 有线网口 → Orin 拓展网络 → AS2-W PC1 DDS → 状态/手柄` 是待实测输入链；未来反向的 LowCmd 链路**尚未实现**。Orin 不运行策略，个人 PC 用于传包与诊断。最终模块顺序为：状态源和 16 轴标定 → 遥控器输入 → 经固件证实的 LowCmd/CRC/控制权和物理退出 → FSM/技能切换 → 平地安全验证 → 恢复策略 → 重新训练通过的爬楼策略。`部署架构.md` 描述代码职责；`现场部署清单.md` 是明天的实际操作顺序。

## 明天须补的事实

1. CPRO 的鸿蒙/Ubuntu 进入命令、用户权限、共享目录、网卡和 DDS 多播可见性，HDC 或 SSH 的可靠传包路径。
2. Orin 扩展模块版本、网线连接口与从 CPRO 到 PC1 的实际路由。能 ping 不等于 DDS 多播可达。
3. 现场固件版本、`LowState` topic/IDL、16 个实体轴在 35 槽中的索引、方向和零位、IMU 坐标、轮轴控制模式/单位/限值。
4. 原厂运控释放/恢复、硬件急停、断联制动、低层写入频率和 CRC；恢复策略另需低层接管后仍可用的机体系线速度来源。
5. 同事新的 5000/8000 轮权重与固定种子仿真结果、完整训练导出/仿真归档。没有通过爬楼门槛的权重不进入真机楼梯阶段。
