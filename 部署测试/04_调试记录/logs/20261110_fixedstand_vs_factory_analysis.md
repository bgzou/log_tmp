# AS2-W 原厂站姿 vs 当前 FixedStand 离线复核

日期：2026-11-10。纯离线读取历史 HG LowState；没有 DDS 发布、ReleaseMode 或机器人动作。

## 结论

现场观察正确。当前 A 键 FixedStand 最终姿态不等于原厂站姿，首要原因不是“没有追到同一个目标”，而是**两者目标本来就不同**：

- 原厂实测站姿 T1：hip 约 `±0.12`，thigh 约 `0.60`，calf 约 `-1.23`。
- 当前 launcher 固定传 `--stand t2`；T2 是策略训练默认姿态：hip `0`，thigh `0.80`，calf `-1.60`。
- FixedStand 最终保持为腿 `kp=55,kd=2`，无显式重力前馈；真机负载下产生约 `0.26–0.30 rad` 的稳态误差，所以实际姿态又进一步偏离 T2。
- 官方内部的 q_cmd/kp/kd/tau_ff 不在 HG LowState 中，不能从现有日志恢复。现有日志只证明官方实际站姿、q/dq/tau_est；不能声称官方具体增益是多少或其控制器是简单固定 PD。

稳态时 dq≈0，`kd*dq` 项几乎为零，因此 **kd 不是最终姿态差异的主因**。kp 和缺少前馈决定负载下的静态偏差，但目标 T1/T2 不同是更前置的原因。

## kp 与静态误差证据

第三次 A→Y 稳定窗逐轴位置标准差低于约 `1.2e-5 rad`，说明这是稳定平衡点，不是振荡。`55 × (T2−q_actual)` 与 `tau_est` 的幅值吻合：

- RL hip：预测约 `14.88 Nm`，实测约 `14.74 Nm`。
- RR calf：预测约 `14.81 Nm`，实测约 `14.53 Nm`。
- 前腿负载约 3–7 Nm，后腿约 14–15 Nm；后腿偏差更大，和实机质心偏后相符。

因此当前 FixedStand 本质是“用纯位置 PD 通过位置误差产生抗重力力矩”。提高 kp 会缩小误差，但不能把 T2 自动变成原厂 T1，也不能证明盲目提高增益安全。

这也可能是 R284 仿真/真机差异的一个放大因素：真机 B 前并非理想 T2，而是 pitch 约 −5°、后腿偏差约0.27rad的负载平衡点；R284 在全量接管时从这个状态闭环。它不能单独解释剧烈振荡（两秒handoff仍温和、全策略后才发散），但下一轮离线复现应把该实测 q/quat 作为 MuJoCo 初态，并把真实记录逐帧做 shadow，而不是继续从理想 T2 起步。

## 架构建议（未实施）

1. 区分两个语义，不再把一个 `stand_pose` 同时承担所有职责：
   - `FactoryLikeStand`：A 键的人机操作站姿，目标 T1。
   - `PolicyReadyStand`：每个策略自己的 nominal pose、kp/kd/tau_ff；B 前通过受控插值进入。
2. 姿态与增益全部放入每策略配置，不把 55/2 写成跨策略常量。
3. 若要求 T1 实际跟踪接近原厂，应优先研究重力前馈或逐轴命令补偿；不能根据 LowState 猜官方 kp/kd。
4. 任何 T1→PolicyReady→策略链先用历史实测姿态作为初态做离线/MuJoCo复演，再设计有界实机验收。当前 R284 真机硬阻断不因本次分析解除。
